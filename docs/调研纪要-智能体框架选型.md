# 调研纪要：智能体框架选型（2026-09）

> 状态：**存档**（决策已由 ADR-0002 做出，本文是调研依据）
> 关联：`智能体平台架构方案.md`、`adr/0001`、`adr/0002`

## 1. 范式变迁（为什么旧方案作废）

### 2025 范式：多智能体编排（已过时）

- 代表：CrewAI crews、AutoGen group chat、LangGraph 预定义图、固定角色 deep research 流水线。
- 旧 `deepresearch设计文档.md`（Commander→Researcher→Critic→Writer）属于此类。

### 2026 范式：单 agent harness + 四个标准件

```
一个强模型的 agent loop
  ├── 工具面：MCP
  ├── 知识面：Agent Skills（SKILL.md，40+ 平台开放标准）
  ├── 并行面：按需 subagent 扇出（非预定义角色）
  └── 执行面：沙箱
```

### 关键证据

| 证据 | 数据 | 来源 |
|---|---|---|
| NMI 2026-07 研究（260 配置/六基准/五架构/三模型系） | 多 agent 仅在可并行拆分任务 +80.8%；顺序依赖任务最高 **-70%**；SWE-bench Verified 四类多 agent 架构 **全部负收益**（-1.3%~-12.8%） | Nature Machine Intelligence（经钛媒体综述） |
| Anthropic 多 agent 研究系统 | 广度搜索 +90.2%，但普通 agent token ≈ 聊天 4×，多 agent ≈ **15×** | Anthropic 工程博客（经钛媒体综述） |
| 业界重写潮 | 产品从 5 agent 重写为 1 loop 的公开案例 | Respan《From Five Agents to One Loop》 |
| "Loop vs Graph"之争（2026-07） | 结论温和：Graph 不是 Loop 替代品，是"多个 Loop 怎么交接"；节点内部仍是 Loop | 钛媒体《Loop 才火了六周》 |

**操作结论**：不做预定义多角色流水线；subagent 只在主 agent 运行时判定有广度需求时按需扇出。

## 3. 代码智能体框架（OpenCode / DSH / Goose 等）是否适合当后端

**结论：不适合整体当后端，三种正确用法。**（详见对话调研，要点如下）

### 为什么不适合整体二开

1. **形态错配**：OpenCode= TUI、Goose = CLI/桌面、DSH = 单用户交互式 harness；产品需要多租户多会话并发 + WebSocket 流式 + MySQL 持久化的服务端。
2. **工具面错配**：coding harness 工具集是文件系统中心（read/write/edit/bash/grep）；通用智能体需要检索/Web/业务 API/沙箱，bash 对多租户 SaaS 是高危面。
3. **成本模型错配**：harness 哲学 "everything on, you subtract"（Claude Agent SDK 35k token 实测）；通用对话智能体需要薄 loop（1.3k token 档）。
4. **DSH 源码注意**：npm 包 `@deepseek-ai/dsh` 的 `lib/` 全是打包产物（plugin-*.js 等），无 src；MIT license（2026 DeepSeek）；二开需源码仓库而非发布产物。

### 三种正确用法

1. **借架构不借代码**（进行中）：工具 schema 设计、权限门控、subagent 扇出、上下文压缩、trace 时间线——已有部分被吸收进 KnowledgeChatPanel / chat_service。
2. **Agent Skills 标准**：DSH/Claude Code/Codex/Gemini CLI/Cursor 共用的 SKILL.md 开放标准（40+ 平台）——平台技能层直接对齐，吃生态。
3. **独立执行层**（未来可选）：若 DIY 要支持"编码型 agent"（操作代码库/计算机），届时把 harness 沙箱执行器（DSH fork / OpenCode server 模式）作为独立执行 tier 接入；非本期。

## 4. 沙箱运行时横评（2026-09）

来源：Qovery《9 Best Ephemeral Code Execution Environments (2026)》+ 补充。

隔离强度：`microVM > gVisor > 共享内核容器 >> 同进程 WASM`（普通容器**不是**不可信代码的安全边界；runc CVE-2019-5736 / CVE-2024-21626）。

| 方案 | 隔离 | 冷启 | 开源/自建 | 备注 |
|---|---|---|---|---|
| E2B | Firecracker microVM | <200ms | Apache-2.0 可自建 | 代码解释器标杆；无 GPU |
| Daytona | 容器（VM 选项） | <90ms（暖池） | 核心 2026-06 转私有 | 有状态持久沙箱 |
| Modal | gVisor | ~1s | 闭源 | GPU 强（T4-B200） |
| Cloudflare Sandbox | V8 isolate / 容器 | ~0（isolate） | 闭源 | 边缘高扇出 |
| Vercel Sandbox | Firecracker | ms 级 | 闭源 | 绑 Vercel 生态 |
| **WASM（Wasmtime，自建）** | 线性内存边界 + 进程边界 | ms 级 | **wasmtime Apache-2.0** | **本平台选择**；fuel/epoch 确定性计量 |

**WASM 安全事实（决策依据）**：
- DEF CON 34 / Cyera：一个 Pyodide 缺陷打穿七个产品（Pyodide 假设输入可信；shell/Python 共享线性内存与 FS）。
- wasmsh SECURITY.md：Pyodide target 下 Python 不受 shell 资源限制约束；沙箱化责任在宿主。
- Cohere Terrarium（2026-04）：沙箱实现缺陷 → 根代码执行。
- 结论：WASM 边界有效**当且仅当** out-of-process + 每调用独立 store + 宿主中介 I/O（ADR-0001 的全部内容就是为了兑现这个"当且仅当"）。

**Pyodide 能力边界**（官方 wasm-constraints）：
- 无 threading / multiprocessing / sockets；ssl 为 stub；网络全走浏览器 fetch（CORS 限制、无证书/超时/代理控制）。
- 包：Pyodide 内置（numpy/pandas 等）+ 纯 wheel（micropip）；普通 C 扩展不可用。
- 产品定位：用户工具 = "数据变换/计算"型。

## 5. 声明式 Agent 定义：Pydantic AI AgentSpec（官方文档核实）

```yaml
model: anthropic:claude-opus-4-6
instructions: "You are helping {{user_name}}."   # Handlebars 模板
deps_schema: {...}     # 模板变量构造期校验
output_schema: {...}   # 结构化输出（注意：不做运行时校验）
capabilities:
  - WebSearch: { local: duckduckgo }
  - MyCapability: {...}   # 自定义 capability 可注册
retries: 2
tool_timeout: 30
```

- `Agent.from_file()` / `from_spec()`；`AgentSpec.to_file(schema_path=...)` 生成编辑器 JSON Schema。
- instructions/capabilities 有明确 merge 语义（spec 在前、kwarg 在后）。
- 原生 token/请求预算硬上限（多租户关键件）。

## 6. OpenAI Agents SDK 接 LiteLLM（官方文档核实）

- 路径 A（采用）：`set_default_openai_client(AsyncOpenAI(base_url=proxy))` + 模型字符串 = proxy 模型 id；不引入 litellm 库。
- 路径 B（不采用）：`openai-agents[litellm]` + `LitellmModel`，官方 beta，小众 provider 有坑。
- subagent = agent-as-tool（`@function_tool` 包装 Agent），已验证等价于按需扇出。

## 7. 其他记录在案（非本期）

- **ACP（Agent Client Protocol）**：Zed 主推的 agent-编辑器互操作，registry 已上线；未来 DIY agent 接编辑器类前端时的标准件。
- **LangGraph 1.2 / ADK 2.0 graph 引擎**：若未来出现真正可拆分、需 checkpoint 的长流程（如多阶段审批流水线），作为按需组件评估；不作地基。
- **Coze Studio（开源）/ Dify 1.16 / Nexora（MIT）**：DIY 平台的产品形态与 marketplace 思路对标。
