## 0. 规划原则

1. **分层贴合架构方案 §2**：api（路由）/ src（业务：runtime、tools、skills、diy、sandbox）/ db（持久化基建）三层不变，延续仓库现有风格；
2. **保留现有基建**：`db/mysql/connection`、`db/redis`、`src/utils`（config_manager / env_manager）原样复用，不重复造轮子；
3. **沙箱红线落实到目录**（ADR-0001）：sidecar 必须是**独立可执行包**（`python -m src.sandbox.sidecar`），与 API 侧代码物理同仓库但进程隔离；Pyodide 再隔一层 Node 孙进程；
4. **测试即验收**：M1 的七条恶意样本验收直接落为 `test/malicious/` 下的测试文件，测试通过 = 里程碑通过。

### 进程拓扑（ADR-0001 §决策 的代码映射）

```
进程 A  API 服务器（FastAPI, :8002）
        └─ src/tools/builtin/code_execute.py（M2 的工具封装）
             └─ SandboxClient（client.py）
                  └─ SidecarManager（manager.py）── spawn/池化/监督
                       │
进程 B                 ▼
        sidecar（python -m src.sandbox.sidecar，低权限用户）
        ├─ wasmtime_engine  ── JS/TS 代码（wasm32-wasi，每调用新 Store）
        └─ pyodide_engine
             │  spawn（每调用或池化）
进程 C      ▼
            node runner.js（Pyodide 运行时，孙进程，最低权限）
```

- A↔B、B↔C 通信一律 **stdin/stdout JSON 帧**（contracts.py 定义），无端口监听、无 UDS 文件——减少暴露面；高并发优化期可评估 UDS，协议帧不变。
- **红线对应**：Pyodide 永不进进程 A（DEF CON 34 教训）；Wasmtime 只在进程 B；网络/文件零默认，一切 I/O 经 hostfuncs.py 的显式宿主函数。

## 7. 实施记录（2026-10-02，M1 完成）

**测试结论：`46 passed, 1 skipped`（skip = macOS 上的 Linux RLIMIT_AS 用例，平台预期）。**

### 7.1 wasmtime-py（49.0.0）的四个坑与修法

| 坑 | 现象 | 修法 |
|---|---|---|
| C API Store 缺 WASI 状态 | 调 wasi:clocks 等 host 时 Rust panic（store.rs unwrap None），46-49 全存在 | `store.set_wasi(WasiConfig())` + `store.set_wasi_http()` 是硬性要求 |
| component linker 句柄锁 | instantiate 报 "cannot use linker while in use" | `with linker.root() as r: with r.add_instance(...) as ns:` 作用域销毁后再 instantiate |
| fuel 耗尽 C API panic | 死循环烧尽 fuel 不返回 trap 而是整个进程 SIGABRT | 上游 bug；墙钟 epoch 是干净 trap 主防线，panic 由进程池自杀重启兜底（调用方收 ENGINE_CRASH，池自愈） |
| import 全名匹配 | 注册 `folio:sandbox/host` 匹配不上 import `folio:sandbox/host@x.y` | WIT package 不带版本号（StarlingMonkey 对带版本说明符解析亦有坑） |

### 7.2 参数校准（实测数据）

- **fuel 默认 1e8 → 1e9**：echo（最小 JS 工具）一次实测 9.4M fuel（初始化 8.5M）；`"x".repeat(2MB)` 成本 >2e9（按字符计费）——默认给用户工具百倍余量，死循环防失控语义不变（10s 墙钟内死循环烧 fuel 远超 1e9）。
- **Node 堆独立计算**：`--max-old-space-size = max(256, memory_limit_mb)`——Pyodide 运行时自身常驻 ~200MB，直配 64 会误杀；Python 侧真实限制 = Linux RLIMIT_DATA（mem + 512MB 余量）+ wasm 堆编译期上限（2GB）。
- **asyncio 流行上限**：manager 读 sidecar 的 StreamReader 默认 64KB 行上限，1MB+ result 帧触发 LimitOverrunError 误判进程死亡 → `create_subprocess_exec(limit=32MB)`。

### 7.3 设计修正（测试反推）

- **selfdestruct 只对 ENGINE_CRASH 计数**：用户代码的业务错误（fuel/timeout/oom/bad_code/denied_*）是正常语义；恶意样本测试（大量预期失败请求）曾把连续失败计数推到阈值、误杀健康 sidecar。
- **runner.js 的 done 帧写完再退出**：Node pipe 异步写，`process.exit(0)` 会截断未 flush 的大帧（2MB done 帧 JSON 被腰斩）——写完成回调里 exit。
- **Pyodide 宿主注入走 globalThis**：`pyodide.globals.set()` 写的是 Python `__main__` 命名空间，`from js import folio_fetch` 看不到。
- **UserFunc 首参是 store**：wasmtime-py host 回调签名 `func(store, *wit_args)`。

### 7.4 Pyodide 行为事实（测试语义依据）

- `os.system()` 不抛异常返回 0（静默 stub，无真实执行——无 execve 面）；
- `socket.socket()` 可创建对象但 `connect()` 必然 OSError（无 syscall 面）；
- `bytearray(2.5GB)` 分配前被 OverflowError 拦（int 索引上限），真实堆上限 2GB（emscripten 编译期）；
- `pyodide.http` 与 `globalThis.fetch/WebSocket/process` 均被 runner 硬化禁用，唯一网络出口 `folio_fetch`（stdin/stdout 转发回 sidecar 做 allowlist/SSRF 检查）。
